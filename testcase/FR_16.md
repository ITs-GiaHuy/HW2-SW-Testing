# Test Cases cho FR-16 — Import Sản phẩm từ CSV
**Phương pháp:** Domain Testing (Equivalence Partitioning & Boundary Value Analysis)

**Endpoint:** `POST /api/admin/import-products`
**Giao diện:** Trang quản lý Sản phẩm trên Web Admin (`http://localhost:5174`)

---

## 1. Xác định Biến Đầu vào & Đầu ra (Step 1)

### Đầu vào (Inputs)

| # | Biến | Loại | Mô tả |
|---|------|------|-------|
| I1 | **JWT Token** | Implicit/State | Token xác thực trong header `Authorization: Bearer <token>` |
| I2 | **Role trong Token** | Implicit/State | Vai trò của người dùng (`admin` hoặc `user`) được mã hóa trong JWT |
| I3 | **Đuôi file (File Extension)** | Explicit | Phần mở rộng của file được tải lên (phải là `.csv`) |
| I4 | **Dòng Header của CSV** | Explicit | Dòng đầu tiên của file CSV, phải là: `name,price,description,imageUrl,category_id` |
| I5 | **Nội dung file (Data Rows)** | Explicit | Các dòng dữ liệu sau header, mỗi dòng là một sản phẩm |
| I6 | **`name` (mỗi dòng)** | Explicit | Tên sản phẩm — bắt buộc, không được rỗng, tối đa 255 ký tự (FR-15) |
| I7 | **`price` (mỗi dòng)** | Explicit | Giá sản phẩm — bắt buộc, phải là số dương (> 0) |
| I8 | **`description` (mỗi dòng)** | Explicit | Mô tả sản phẩm — tùy chọn |
| I9 | **`imageUrl` (mỗi dòng)** | Explicit | Đường dẫn ảnh — tùy chọn |
| I10 | **`category_id` (mỗi dòng)** | Explicit | ID danh mục — bắt buộc, phải tồn tại trong hệ thống (FR-15) |
| I11 | **Trường chứa dấu phẩy** | Explicit | Trường có dấu phẩy phải được bọc trong dấu nháy kép (RFC 4180) |
| I12 | **Số lượng dòng dữ liệu** | Explicit | Số dòng sản phẩm trong file (>= 0) |

### Đầu ra (Outputs)

| # | Đầu ra | Loại | Mô tả |
|---|--------|------|-------|
| O1 | **Phản hồi HTTP Status** | Visible | 200 (thành công), 400 (lỗi dữ liệu), 401 (chưa xác thực), 403 (không có quyền) |
| O2 | **Báo cáo kết quả import** | Visible | Số dòng thành công, số dòng lỗi, lý do lỗi cụ thể từng dòng |
| O3 | **Dữ liệu sản phẩm trong CSDL** | Hidden | Sản phẩm mới được thêm hoặc không thay đổi (rollback) |
| O4 | **Rollback khi có lỗi** | Hidden | Nếu bất kỳ dòng nào lỗi → toàn bộ giao dịch bị hủy, không có sản phẩm nào được thêm |
| O5 | **Thông báo lỗi validation** | Visible | Thông báo cụ thể: tên rỗng, giá không hợp lệ, v.v. |

### Ghi chú thêm:
- **Rollback (TC30, TC31, TC32, TC34):** Đây là yêu cầu quan trọng nhất của FR-16. Cần kiểm tra CSDL sau import để xác nhận **không có sản phẩm nào** được thêm khi có bất kỳ dòng lỗi nào (all-or-nothing). Xem lại implementation ở `server.js` dòng 198–241: hiện tại backend **không sử dụng transaction** và không rollback — đây là bug tiềm ẩn.
- **Kiểm tra role admin (TC03):** Backend tại dòng 199 chỉ kiểm tra `authenticateToken` nhưng **không kiểm tra `role = 'admin'`** — đây có thể là lỗi bảo mật theo SEC-03.
- **CSV Parsing (TC26–TC28):** Frontend parse CSV bằng `split(",")` đơn giản (dòng 371 App.jsx), **không hỗ trợ RFC 4180** (dấu nháy kép). Đây là bug cần ghi nhận.
- **Validation price (TC18–TC21):** Backend hiện tại (dòng 214–217) **chỉ validate `name`**, không validate `price` — cần kiểm tra kỹ.
- **Đuôi file (TC04, TC05):** Việc kiểm tra đuôi file `.csv` chỉ xảy ra ở frontend (qua thuộc tính `accept` của input file hoặc logic frontend). Backend nhận JSON nên không kiểm tra đuôi file trực tiếp.
