# Test Cases cho FR-11 — Xem lịch sử đơn hàng (User)
**Phương pháp:** Domain Testing (Equivalence Partitioning & Boundary Value Analysis)

---

## 1. Xác định Biến Đầu vào & Đầu ra (Step 1)

### Đầu vào (Inputs)

| # | Biến | Loại | Mô tả |
|---|------|------|-------|
| I1 | **JWT Token** (Header `Authorization: Bearer <token>`) | Implicit/State | Token xác thực gửi kèm request. Xác định danh tính người dùng. |
| I2 | **Vai trò người dùng (Role)** | Implicit/State | Role được mã hóa trong JWT Token (`user` hoặc `admin`). FR-11 dành cho User. |
| I3 | **Số lượng đơn hàng của User** | Implicit/State | Số đơn hàng thuộc về user hiện tại trong DB (0, 1, hoặc nhiều). |
| I4 | **Trạng thái đơn hàng (status)** | Implicit/State | Một trong 5 giá trị: `pending`, `confirmed`, `shipping`, `delivered`, `canceled` (FR-10). |
| I5 | **Tổng tiền đơn hàng (total_amount)** | Implicit/State | Giá trị số nguyên (INTEGER) lưu trong DB, đơn vị VNĐ. |
| I6 | **Ngày đặt hàng (created_at)** | Implicit/State | Datetime tự động gán khi tạo đơn. |
| I7 | **Mã đơn hàng (id)** | Implicit/State | ID tự tăng (INTEGER) trong bảng `orders`. |

### Đầu ra (Outputs)

| # | Đầu ra | Loại | Mô tả |
|---|--------|------|-------|
| O1 | **Danh sách đơn hàng** | UI (Bảng) | Bảng hiển thị các cột: Mã ĐH, Ngày đặt, Tổng tiền, Trạng thái, Thao tác. |
| O2 | **Mã đơn hàng** | UI (Text) | Hiển thị dạng `#<id>` (font mono). |
| O3 | **Ngày đặt** | UI (Text) | Ngày format theo `toLocaleDateString()`. |
| O4 | **Tổng tiền** | UI (Text) | Định dạng phân cách hàng nghìn + ký hiệu `₫` (FR-21). |
| O5 | **Nhãn trạng thái tiếng Việt** | UI (Badge) | Dịch: pending→"Chờ xác nhận", confirmed→"Đã xác nhận", shipping→"Đang giao", delivered→"Đã giao", canceled→"Đã hủy". |
| O6 | **Màu sắc trạng thái** | UI (CSS) | Mỗi trạng thái phải có màu riêng biệt, phân biệt rõ ràng. |
| O7 | **Empty State** | UI | Khi không có đơn hàng: hiển thị icon/hình minh họa + message thân thiện (FR-24). |
| O8 | **Thẻ `<h1>`** | UI (HTML) | Trang phải có đúng 1 thẻ `<h1>` mô tả nội dung trang (FR-21). |
| O9 | **Phân quyền dữ liệu** | Logic | User chỉ thấy đơn hàng của chính mình, không thấy đơn của user khác. |
| O10 | **Phản hồi API khi không xác thực** | API Response | Trả về HTTP 401/403 khi không có hoặc token không hợp lệ (SEC-02). |

## 3. Danh sách Test Case (Step 3 & 4)

*Lưu ý: Đã áp dụng phân tích giá trị biên (LB-1, LB, LB+1) cho số lượng đơn hàng. Đã kết hợp các lớp hợp lệ (Valid) vào chung test case khi có thể để giảm số lượng TC. Mỗi TC không hợp lệ (Invalid) chỉ chứa đúng 1 lớp invalid, các input còn lại đều valid.*

### Ghi chú thêm:
- **Empty State (TC11):** Cần kiểm tra kỹ xem trang có hiển thị icon/hình minh họa theo FR-24 hay chỉ hiển thị text "Bạn chưa có đơn hàng nào" (hiện tại code chỉ render `<p>` text, thiếu icon — đây có thể là bug).
- **Thẻ `<h1>` (TC18):** Hiện tại trang Profile dùng `<h2>` cho tiêu đề "Lịch sử đơn hàng" và không có `<h1>`. Cần kiểm tra xem trang có vi phạm FR-21 (thiếu `<h1>`) không.
- **Cột hiển thị (TC25):** Trong code, bảng có thêm cột "Thao tác" (nút Hủy đơn) — cột này nằm ngoài phạm vi FR-11 nhưng không phải lỗi.
- **Data isolation (TC12-TC13):** Backend filter bằng `WHERE user_id = ?` lấy từ JWT token — cần verify rằng không có cách nào inject user_id khác qua query parameter.
