## Bug Description
The `/api/admin/import-products` endpoint verifies that a user is authenticated (via JWT token) but completely fails to check if the user actually has the Admin role (`req.user.role === 'admin'`). Any regular user with a valid login token can successfully upload a CSV file and inject products into the database.

## Steps to Reproduce
1. Login as a regular user (e.g., `test@eshop.com`) to get a JWT token.
2. Send a `POST` request to `/api/admin/import-products` with a valid CSV file payload, attaching the regular user's token in the `Authorization` header.

## Expected Result
API should return `403 Forbidden` (or 401 Unauthorized) because the user is not an admin.

## Actual Result
API returns `200 OK` and successfully processes the CSV file, adding products to the system.

## Environment
- SUT: Backend Express API
- OS: Linux

## Test Evidence
- Test Case: TC03 from FR-16
- Assertion Error: `Expected: 403, Received: 200`
- Code review of `backend/server.js` confirms `authenticateToken` middleware is used, but no role authorization middleware is present.

## Severity
Critical — Massive security vulnerability allowing arbitrary data injection by any authenticated user.
