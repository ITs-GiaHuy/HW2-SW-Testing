## Bug Description
The CSV Import feature in the backend does not use SQL Transactions (`BEGIN TRANSACTION` / `COMMIT` / `ROLLBACK`). If a CSV file contains a mix of valid and invalid rows, the valid rows are inserted into the database, while the invalid rows are skipped. This violates the "All-or-Nothing" atomic requirement.

## Steps to Reproduce
1. Upload a CSV file containing 3 rows: Row 1 is valid, Row 2 has a missing name (invalid), Row 3 is valid.
2. Submit the import.
3. Check the database for the products.

## Expected Result
The import fails entirely, the database is rolled back, and 0 products are added.

## Actual Result
The API returns a partial success, inserting Row 1 and Row 3 into the database.

## Environment
- SUT: Backend Express API (`server.js`)
- OS: Linux

## Test Evidence
- Test Case: TC30, TC31, TC32, TC34 from FR-16
- Playwright Error: `Timeout 30000ms exceeded` waiting for rollback error message, since backend reports partial success.

## Severity
High — Breaks data integrity requirements and leaves the database in an inconsistent state.
